# Справка: новый Hammer и Source 2 — то, что нужно генератору

Собрано в ноябре 2026. Сайт Valve (developer.valvesoftware.com) закрыт от
роботов, поэтому у каждой строки указано, откуда она:

* **✔ его файл** — записал сам его Hammer (primer.vmap, editorbuild 10961) или
  проверено его глазами;
* **≈ Valve, CS:GO** — справочник Valve для CS:GO; движение в CS2 почти то же,
  но в самой CS2 мы не мерили;
* **? не проверено** — по памяти или по чужим разборам. Проверять перед тем,
  как на это опираться.

Проверить число в игре: `cl_showpos 1` (координаты и скорость на экране),
`getpos` (точка и взгляд в консоль).

## 1. Игрок: рост, шаг, прыжок, буст

От этих чисел зависят высота стен, укрытий и подоконников.

| что | юнитов | откуда |
|---|---|---|
| ширина игрока | 32 × 32 | ≈ Valve, CS:GO |
| рост стоя | 72 | ≈ Valve, CS:GO |
| рост присев | 54 | ≈ Valve, CS:GO |
| глаза стоя / присев | 64 / 46 | ≈ Valve, CS:GO |
| ступенька без прыжка | **18** | ≈ Valve, CS:GO (у нас так и строится) |
| прыжок | ~55 | ≈ Valve, CS:GO |
| прыжок с приседом | ~65 | ≈ Valve, CS:GO |

Что из этого следует для карты (считается, а не меряно):

| куда залезет | высота, юнитов |
|---|---|
| один, прыжком с приседом | до ~65 |
| встав на присевшего товарища и прыгнув | 54 + 65 ≈ **120** |
| встав на стоящего товарища и прыгнув | 72 + 65 ≈ **137** |
| пирамида из трёх | ~210 |

Отсюда правило для его просьбы «стены не до неба, но высоко, и чтобы не
бустили»: видимая стена — по смыслу места (192–256 хватает, чтобы с буста не
заглянуть), а над ней **невидимая стена для игрока** (`toolsplayerclip`) до
верха коробки неба. Солнце через неё проходит, пули тоже, игрок — нет.
В `core/yadro.js` это уже так: `клип` 256 над стеной.

## 3. Сущности режима «закладка бомбы»

| сущность | что это | что важно | откуда |
|---|---|---|---|
| `info_player_terrorist`, `info_player_counterterrorist` | спавн | ключи `priority` (меньше — занимается раньше) и `enabled` | ✔ его файл (оба ключа есть, `priority 0`) |
| `func_buyzone` | зона закупки | `TeamNum` 2 = T, 3 = CT; это меш с материалом `toolstrigger` | ✔ его файл |
| `func_bomb_target` | плент | меш `toolstrigger` | ✔ его файл |
| `env_cs_place` | название места | меш `tools_cs_place`, имя видно на радаре | ✔ его файл |
| `light_environment` | солнце и свет неба | см. раздел 4 | ✔ его файл |
| `env_sky` | картинка неба | `skyname`, `tint_color`, `brightnessscale` | ✔ его файл |
| `post_processing_volume` | цвет и экспозиция | у нас пока не ставится | ✔ его файл |
| `prop_static` | готовая модель из игры | `model` = путь `.vmdl`, `solid 6` = твёрдая | ✔ его файл (лестница `models/de_anubis/structures/stairs03_160.vmdl`) |

Спавнов у нас по 8 на сторону, у всех `priority 0`. Для 5×5 Valve советует:
пять «турнирных» оставить с 0, остальным поставить 1 — тогда соревновательный
режим ставит игроков всегда в одни и те же пять точек. У нас это сейчас
случайный выбор из восьми. **Решение за ним** — это про баланс старта.

## 4. Свет

Ключи солнца, как их пишет его Hammer:

| ключ | у нас (v139) | Mirage | Dust2 | смысл |
|---|---|---|---|---|
| `brightness` | 1.18 | 2.47 | 2.25 | сила солнца (= `_light`/255 из `.vmf`) |
| `skyintensity` | **0.24** | 0.84 | 0.96 | подсветка тени небом (= `_ambient`/255) |
| `color` / `skycolor` | | | | цвет солнца / цвет неба |
| `skytexture` | пусто | | | можно брать свет неба с картинки неба |
| `angulardiameter` | 2 | | | размытость теней |

✔ его файл (переводы `/255` сверены). Значения Mirage и Dust2 — из их
исходников в `data/etalon_src`. **Отложено до его слова.**

Чего у нас нет вообще и что, скорее всего, нужно для игроков в тени:

* **`env_combined_light_probe_volume`** — коробка вокруг всей играбельной части,
  из неё берут свет модели игроков, оружие, гранаты. Без неё они освещаются
  неправильно (обычно темнее стен рядом). Объединяет `env_light_probe_volume`
  (рассеянный свет) и `env_cubemap_box` (отражения). ? Нужна ли одна на карту или
  по одной на зону — не проверено; в игре видно командой
  `r_light_probe_volume_debug_grid 1`.

Это тоже свет — **ждёт его слова** вместе с яркостью.

## 5. Формат `.vmap` — что знаем точно

✔ всё ниже проверено его Hammer.

* Текстовый `.vmap` — это DMX KeyValues2 (`<!-- dmx encoding keyvalues2 4 format vmap 40 -->`).
  Пишем его сами: `core/vmap.js`; перевод готового `.vmf` — `core/vmf2vmap.js`.
* Геометрия — **меши**, а не браши. Меш может быть любой формы, в том числе
  невыпуклый, с гранями-многоугольниками. Браш `.vmf` при импорте становится
  одним выпуклым мешем.
* Масштаб текстуры в `.vmap` = масштаб `.vmf` × 16 / (точек в картинке).
  Сдвиг тоже умножается на (точек)/16. Таблица точек — `data/tekstury_tochek.json`.
* Брашевые сущности (закупка, плент, место) без `origin` импортёр ставит в 0 0 0.
* Импортёр сам добавляет пустой `env_sky` «default_sky»; небо он не выбирает.
  Его небо: `materials/dev/default_sky.vmat`.

## 6. Что в новом Hammer есть такого, чего не было в старом

| возможность | что даёт генератору |
|---|---|
| **меши любой формы** | комнату, стену с проёмами, пандус можно писать одним куском, без нарезки на коробки. Это то самое «склеивание коробок», о котором он просил для редактора |
| **хотспот-материалы** (hotspot) | текстура сама садится на грань по её размеру: рамы, панели, торцы. Подгонка масштаба вручную (правило 5.3) может стать не нужна. ? Каталог хотспот-материалов CS2 не смотрели |
| **модели `.vmdl`** | бордюры, лестницы, перила, ящики Valve — готовыми, вместо брашей. Путь модели берётся из его файла |
| **префабы** (`.vmap` внутри `.vmap`) | один раз собранный предмет ставится много раз. ? формат вставки не смотрели |
| **предпросмотр запечённого света в Hammer** | меню «Preview Baked Lighting» сверху окна: свет видно без полной сборки |

## 7. Радар

Генератор умеет делать радар с v81 (картинка `_radar.png` и привязка `.txt`
с `pos_x`, `pos_y`, `scale`), сейчас — вместе с кнопкой `.vmf`. Формат `.txt`
тот же, что в CS:GO. ? Куда класть файлы в аддоне CS2 (`panorama/images/overheadmaps/`
и `resource/overviews/`) — по разборам сообщества, у Valve не проверено.
Картинка обязана быть квадратной.

## 8. Как пройти карту в игре (порядок, который у него работает)

1. Открыть `.vmap` в Hammer (аддон CS2 Workshop Tools).
2. Сборка карты: меню **File → Build Map** (F9). Полная сборка печёт свет — это
   долго; для пробежки свет можно ставить на низкое качество.
3. В игре: консоль, `map <имя_карты>`.
4. Для ботов — навигация (в окне сборки галочка навигации). ? путь в меню не сверяли.
